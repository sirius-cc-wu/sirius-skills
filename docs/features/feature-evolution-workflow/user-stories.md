# User Stories: Feature Evolution Workflow

- **FEW-01 (M)**: As a planner, I want to initiate a change against an existing
  feature so that evolving requirements can be handled without replacing the
  canonical feature docs ad hoc.

- **FEW-02 (M)**: As a reviewer, I want explicit impact analysis for an existing
  feature change so that affected stories, design decisions, and slices are
  visible before new work is bootstrapped.

- **FEW-03 (L)**: As a maintainer, I want feature-change delta artifacts so that
  proposed amendments can be reviewed separately before they are reconciled into
  the canonical feature folder.

- **FEW-04 (L)**: As a planner, I want an explicit reconciliation step so that
  approved changes update canonical feature docs with durable backlinks to the
  closed change history.

- **FEW-05 (L)**: As a maintainer, I want feature-change closure and history
  patterns that borrow the discipline of archive workflows without making the
  canonical feature folder temporary.
