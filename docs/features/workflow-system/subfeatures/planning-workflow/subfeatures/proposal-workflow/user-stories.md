# User Stories: Proposal Workflow

- **PFW-01 (M)**: As a repository maintainer, I want speculative ideas stored under `docs/proposals/` so the feature registry only tracks accepted canonical features.

- **PFW-02 (M)**: As a planner, I want `guide-planning` to route uncertain or exploratory requests to `propose` first so feature planning does not start too early.

- **PFW-03 (M)**: As a reviewer, I want proposal lifecycle states and review notes tracked durably so accept/reject decisions are explicit.

- **PFW-04 (M)**: As a maintainer, I want accepted proposals promoted into canonical feature folders with clear safeguards so the planning workflow stays coherent.

- **PFW-05 (S)**: As a project adopter, I want `proposal_dir` configurable in `.skills/planning.json` so proposal storage can match local repository layout.
