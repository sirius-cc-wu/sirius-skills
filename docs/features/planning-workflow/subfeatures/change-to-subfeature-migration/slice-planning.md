# Slice Planning

## 1. Planning Scope

- Feature: Change to subfeature migration
- Planning sources:
  - `discover.md`
  - `impact-analysis.md`
  - `system-design.md`
  - `user-stories.md`
- Execution system: repository-managed code changes and tests
- Execution mode: `single-agent`
- Notes: MVP covers legacy repos generated by the old
  `evolve-feature` / `reconcile-feature` workflow.

## 2. Story Decisions

| Story ID | Story Size | Story Risk | Decision | Reason | Output Slice Count |
| --- | --- | --- | --- | --- | --- |
| CTSM-01 | M | medium | keep | Legacy scan/reporting is one coherent behavior surface. | 1 |
| CTSM-02 | M | medium | keep | Dry-run is tightly coupled to scan and write planning. | 1 |
| CTSM-03 | L | high | split | Data conversion and file movement need focused validation. | 2 |
| CTSM-04 | M | medium | keep | Registry repair and install/docs updates can be shipped together. | 1 |

## 3. Increment Plan

| Increment | Goal / User-Visible Value | Included Story IDs | Planned Slice IDs | Demo / Verification Outcome | Notes |
| --- | --- | --- | --- | --- | --- |
| I1 | Inspect legacy repos safely | CTSM-01, CTSM-02 | ctsm-scan-legacy-layout, ctsm-dry-run-reporting | A maintainer can list legacy change packets and preview migration without writes. | Simplest usable path |
| I2 | Convert legacy change packets into durable subfeatures | CTSM-03 | ctsm-metadata-conversion, ctsm-path-migration | A feature with old `changes/` packets becomes valid `subfeatures/` output. | Depends on I1 |
| I3 | Make the capability reusable | CTSM-04 | ctsm-skill-docs-and-validation | The migration skill is installed, documented, and covered by tests. | Depends on I2 |

## 5. Dependency Notes

- Critical path: scan -> dry-run -> metadata conversion -> path migration ->
  docs/install/validation.
- Main blocker: migration writes must stay deterministic and must not overwrite
  existing subfeature folders.
- Repo-wide migration depends on planning-scope resolution staying compatible
  with nested feature paths.
