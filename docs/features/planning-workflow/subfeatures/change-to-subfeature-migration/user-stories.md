# User Stories: Change To Subfeature Migration

- **CTSM-01 (M)**: As a maintainer, I want to scan a feature or repo for legacy
  `changes/` packets so that I can see what still needs migration.

- **CTSM-02 (M)**: As a maintainer, I want a dry-run migration mode so that I can
  preview conflicts and planned path changes before modifying planning docs.

- **CTSM-03 (L)**: As a maintainer, I want legacy change packets converted into
  durable subfeatures so that old repositories can use the new planning model
  without manual folder surgery.

- **CTSM-04 (M)**: As a maintainer, I want registries and planning metadata
  repaired after migration so that `guide-planning` and the subfeature tooling
  can operate on the migrated repo immediately.
