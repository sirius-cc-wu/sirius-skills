# User Stories: Feature Consolidation And Reduction

- **FCR-01 (M)**: As a planner, I want each net-new planning capability to name
  what existing capability, artifact, or command surface it supersedes,
  narrows, or removes so that workflow growth stays intentional.

- **FCR-02 (M)**: As a reviewer, I want planning review to flag additive-only
  expansion when a valid consolidation path exists so that the planning
  workflow does not accumulate parallel complexity.

- **FCR-03 (M)**: As a maintainer, I want planning artifacts to record what
  becomes active, historical, archived, or superseded so that later maintenance
  and traceability workflows can use the same durable decision.

- **FCR-04 (S)**: As a repository adopter, I want the user-facing planning
  surface to get simpler when new capabilities land so that I can tell which
  path is canonical without reading historical chat context.
